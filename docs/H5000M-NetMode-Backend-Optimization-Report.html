06性能优化

按「有则写、无则不编」原则，仅列有代码依据或模拟实测数据的优化点。

固定等待：已是「条件检测」模式

旧形态（不存在于当前代码）：操作 → sleep → 查询 → sleep → 操作

当前形态（保持不变）：操作 → 条件检测
                              ├─ READY → 立即继续
                              └─ NOT READY → 短间隔重查（受 budget 双重约束）
                                                ├─ READY → 继续
                                                └─ 超时 → 按序退出 / 回滚

审查结论：仓库内不存在无条件的固定 sleep；所有等待均有界且有语义（见第 03 节审计表），因此没有可安全删除的固定等待。

路由 dump 缓存（本轮核心，模拟实测）

优化前

show_defaults 通过 $(...) 调用时在命令替换子 shell 中构建缓存，缓存随子 shell 消亡 → 每次读取都重新执行 ip route show default。单次 status 进程实测 34 次（v4=17、v6=17）。

优化后

缓存变量 export + read_live_state 主 shell 预热 → 子 shell 继承缓存命中。单次 status 进程实测 2 次（每族 1 次）；ROUTE_GEN 变更后失效重查，语义不变。

减少原因：同一进程内同一 ROUTE_GEN 下，多次命令替换读取改为一次真实内核查询；真实收益（秒级切换耗时）需在目标 OpenWrt 设备上实测，此处不宣称。

热插拔路径 fork 减少

角色分类（iface_role）从 hotplug 的独立子进程移入 notify，每事件后端进程启动 2 → 1 次；非参与接口（lan/loopback/未知）在进入 marker / reconcile 工作前即被跳过（模拟验证通过）。

Shell 高频路径

  • 未新增 awk/sed/grep/cat 重复调用；新增的两个参数函数复用既有 uci_get 进程内缓存。
  • 全部改动保持 POSIX sh / BusyBox ash 兼容，未引入 bash / Python / Node 等额外运行时。

07IPv4 / IPv6

切换始终是「一个事务、两个地址族、同一个物理 WAN」，本轮未改变该保证，仅报告现状并确认后端一致性优化点。

图 2 · IPv4 + IPv6 同一物理 WAN（示意）
  • route：每地址族一个活跃槽位（metric 10）与备用槽位（metric 50），切换 = 原子 replace，无「无默认路由」瞬间。
  • metric：ACTIVE_METRIC=10 / STANDBY_METRIC=50，双栈对称。
  • policy / interface：ipv6_owner=follow_active_group，IPv6 默认路由始终跟随活跃组；来源受限路由（netifd 安装）与程序管理的 plain 路由同 metric 时 tie-break 优先 plain。
  • 一致性保障未因本轮修改而变化：test_align_command_repairs_a_split / test_half_committed_switch_is_rolled_back 等用例持续全绿。
